# 什么是 SQLite：嵌进程序的单文件关系型数据库

SQLite 是一个用 C 语言写的、可以直接嵌进程序里的小型关系型数据库。它不装服务端，不开端口，落地之后往往就是一个几百 KB 的普通文件。它和 MySQL 这类数据库差在哪，内部怎么保证数据不写坏，什么时候该用它、什么时候不该用它，是理解它的几个关键角度。

![SQLite 定义示意：C 语言编写、可嵌进程序、无服务端与端口、落地为几百 KB 普通文件](/blog/什么是-sqlite-嵌进程序的单文件关系型数据库/scene-1-1.png)

## 什么是 SQLite

SQLite 的定位不是独立运行的服务进程，而是一个数据库引擎库。你把它链接进自己的程序，调用函数就能读写数据，中间没有网络，也没有额外的进程，因此大家管它叫嵌入式数据库。

平常说的数据库，多数指一个独立运行的服务进程，比如 MySQL、PostgreSQL：程序通过网络连上去，发 SQL 给它，它再把结果返回。SQLite 不是这种形态。

![架构对比：左侧程序经网络连接 MySQL 等服务进程，右侧程序内部直接嵌入 SQLite 引擎库](/blog/什么是-sqlite-嵌进程序的单文件关系型数据库/scene-3-2.png)

第二个关键点是单文件。一个库就是一个文件，表、索引、视图、触发器全装在里面。复制这个文件就是备份，删掉这个文件就是删库；你可以把它拷进 U 盘，也可以塞进手机安装包。

![单文件示意：一个文件内含表、索引、视图、触发器，复制即备份、删除即删库](/blog/什么是-sqlite-嵌进程序的单文件关系型数据库/scene-4-3.png)

它的体量很小。编译出来通常只有几百 KB 到一两 MB，官方还提供了可裁剪的配置，可以压得更小。运行时也不需要预分配大块内存，用多少拿多少。这在手机、路由器、车机这种资源紧张的环境里，是决定性优势。

![体量示意：编译产物几百 KB 到一两 MB，可裁剪更小，内存按需取用，适用手机、路由器、车机](/blog/什么是-sqlite-嵌进程序的单文件关系型数据库/scene-5-4.png)

它为什么这么流行？核心是零配置：不用安装，不用启动服务，不用建账号设密码，也不需要运维天天盯着。程序打开文件就能用，用完关掉，整套部署和权限流程都被省掉了。

![零配置示意：跨过安装、启动服务、建账号、日常运维，直接打开文件就能用](/blog/什么是-sqlite-嵌进程序的单文件关系型数据库/scene-6-5.png)

## 核心机制：从 SQL 到安全落盘

SQL 语句进来，先被解析成语法树，再编译成一串字节码，最后由一个执行引擎逐条跑完。这套结构让它既能对 SQL 做优化，也方便移植到各种平台。

![执行流程：SQL 语句解析成语法树，编译为字节码，由执行引擎逐条执行](/blog/什么是-sqlite-嵌进程序的单文件关系型数据库/scene-7-6.png)

数据怎么安全落到磁盘上，是它最值得说的部分。SQLite 把文件切成固定大小的页，默认一页 4096 字节，再用一棵 B 树把页组织起来，找一条记录通常只走几层。

![存储结构：数据库文件切成 4096 字节的页，页由 B 树分层组织，查找只需走几层](/blog/什么是-sqlite-嵌进程序的单文件关系型数据库/scene-8-7.png)

所有修改都走事务，要么全部成功，要么全部回滚，写到一半断电也不会把库写坏。

![事务示意：全部成功则数据完整落库，中途断电则全部回滚、数据库保持原状](/blog/什么是-sqlite-嵌进程序的单文件关系型数据库/scene-9-8.png)

它还有一个预写日志模式，也就是 WAL。写操作先追加到一个日志文件里，之后再合并回主库，这样读和写可以同时进行，并发表现明显更好。

![WAL 预写日志：写操作先追加到日志文件再合并回主库，读写可同时进行](/blog/什么是-sqlite-嵌进程序的单文件关系型数据库/scene-10-9.png)

## 实践场景：几乎每台设备的默认位置

使用场景非常广：

- 安卓和 iOS 系统里都自带 SQLite，通讯录、短信、聊天记录、浏览历史背后基本都是它。
- 很多桌面软件拿它存配置和用户数据。
- 一些浏览器用它存书签、历史、扩展数据。
- 单元测试里也常用它替代真实数据库，跑得快，还不用起服务。

![使用场景：安卓与 iOS、桌面软件、浏览器、单元测试四类环境中的 SQLite](/blog/什么是-sqlite-嵌进程序的单文件关系型数据库/scene-11-10.png)

在物联网和边缘设备上，它同样常见：采集设备在路上连不上服务器，就先把数据攒在本地，等有网了再上传。也有不少数据分析工具直接读 SQLite 文件做查询，省掉导入这一步。

另外它是公共领域授权，可以随便商用，没有开源协议的额外约束。

![边缘与授权：设备离线攒数据有网再上传、分析工具直读库文件、公共领域授权可商用](/blog/什么是-sqlite-嵌进程序的单文件关系型数据库/scene-12-11.png)

## 限制与常见误区

但它不是万能的。它的写入是串行的，同一时刻只允许一个写操作，所以高并发写入的场景不适合它。它也不支持多台机器同时访问同一个库文件，放在网络文件系统上还有损坏数据的风险。数据量大到需要复杂分析时，也应该交给专门的系统。

![不适用场景分叉：高并发写入、多机共享同一库文件、大数据量复杂分析](/blog/什么是-sqlite-嵌进程序的单文件关系型数据库/scene-13-12.png)

还有一个常见误解要说清楚：SQLite 不是玩具数据库。它支持完整事务、索引、视图、触发器、外键、窗口函数和 JSON 函数，SQL 覆盖度相当高。它只是把架构押在了单机、单进程、嵌入这条路上，而不是多机、高并发、集中式。

![误区对比：SQLite 并非玩具数据库，支持完整事务、索引、视图、触发器、外键、窗口函数与 JSON 函数](/blog/什么是-sqlite-嵌进程序的单文件关系型数据库/scene-14-13.png)

## 常见问题

- **SQLite 需要安装并启动服务吗？** 不需要。不用安装、不用启动服务、不用建账号设密码，程序打开文件就能用，用完关掉。
- **SQLite 和 MySQL 有什么区别？** MySQL 这类数据库是独立运行的服务进程，程序通过网络连上去、发 SQL、取结果；SQLite 是链接进程序的引擎库，中间没有网络，也没有额外的进程。
- **SQLite 会把数据写坏吗？** 所有修改都走事务，要么全部成功，要么全部回滚，写到一半断电也不会把库写坏；WAL 模式下写操作先追加到日志文件，之后再合并回主库。
- **SQLite 适合高并发写入吗？** 不适合。它的写入是串行的，同一时刻只允许一个写操作；它也不支持多台机器同时访问同一个库文件。

## 总结

SQLite 是一个嵌进程序的单文件关系型数据库，靠零配置、小体量、事务安全和跨平台，占据了几乎每台设备的默认位置；而它被排除在外的场景，恰好都是需要高并发写入或多机共享的地方。
