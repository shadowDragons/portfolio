# 什么是抓包

**什么是抓包？** 简单说，就是把网络里正在流动的数据一个包一个包地截下来，看清楚它们到底传了什么。

它不是什么黑客专属技能，而是排查网络问题、理解协议、验证接口最常用的一把放大镜。

![抓包定义：放大镜对准数据包，辐射排查网络问题、理解协议、验证接口三个用途](/blog/什么是抓包-从数据包-混杂模式到-https-明文的完整解析/scene-1-1.png)

接下来会讲清几件事：数据为什么会被切成包、抓包工具怎么截到这些包、HTTPS 时代还能抓到什么、抓不到什么。

![四格卡片概览：为什么切成包、工具怎么截、HTTPS 能抓什么、抓不到什么](/blog/什么是抓包-从数据包-混杂模式到-https-明文的完整解析/scene-2-2.png)

## 抓包抓到的到底是什么

网络通信不是把一整段内容一次性送过去，而是拆成很多小块，每块叫一个数据包，英文叫 Packet。

你打开一个网页，背后可能是几十上百个包在来回跑。抓包就是把它们按时间顺序记录下来，让你看到每一次请求和每一次回应。

![时间轴上一整段内容被切成多个 Packet 小块，按时间排成请求与回应](/blog/什么是抓包-从数据包-混杂模式到-https-明文的完整解析/scene-3-3.png)

### 数据包是分层封装的结果

每个包都像套了好几层信封。最里面是你要传的内容，比如一段 HTTP 文本；往外套一层 TCP，负责分段和保证可靠传输；再套一层 IP，负责找到对方在哪；最外层是以太网帧，负责在本地网络里送到网卡。

抓包工具就在网卡这一层动手，把流过的帧复制一份存下来。

![数据包的四层嵌套信封：HTTP 文本、TCP、IP、以太网帧，网卡处复制一份帧](/blog/什么是抓包-从数据包-混杂模式到-https-明文的完整解析/scene-4-4.png)

### 网卡为什么要开混杂模式

默认情况下，网卡只收发给自己的数据。

抓包时要把网卡设成混杂模式，也就是从只收自己的，改成路过就先复制一份，这样同一网段里的流量也能被看到。

![网卡模式对比：只收发给自己的数据 与 混杂模式路过先复制一份](/blog/什么是抓包-从数据包-混杂模式到-https-明文的完整解析/scene-5-5.png)

### 常见工具

常见抓包工具各有侧重：

- **Wireshark**：图形界面，看得最细。
- **tcpdump**：命令行，适合放在服务器上。
- **Charles 和 Fiddler**：更偏向看 HTTP 请求。

![抓包工具比较矩阵：Wireshark、tcpdump、Charles/Fiddler 的界面形态与侧重](/blog/什么是抓包-从数据包-混杂模式到-https-明文的完整解析/scene-6-6.png)

## 两种常见抓法：网卡直截与中间代理

一种是直接在网卡上截，适合看底层协议，比如 TCP 重传、DNS 查询，但对 HTTPS 内容无能为力。

另一种是挂一个代理在中间，请求先到代理再转发，它天然能看到明文，更适合调接口。

选哪种，取决于你要回答的问题在底层还是在应用层。

![两种抓法对比：左侧网卡直截看底层协议，右侧中间代理看到明文适合调接口](/blog/什么是抓包-从数据包-混杂模式到-https-明文的完整解析/scene-7-7.png)

## 为什么值得学抓包

抓包是把黑箱变透明的手段。网页打不开、App 登录失败、接口偶尔超时，光看日志往往说不清问题出在哪。

抓一次包，你能看到请求发出去没有、对方回了什么状态码、中间卡了多久。有数据在手，排查就从猜变成了看，所以开发、测试、运维都会用到它。

![从黑箱故障到可见信息：网页打不开、登录失败、接口超时 → 请求、状态码、耗时](/blog/什么是抓包-从数据包-混杂模式到-https-明文的完整解析/scene-8-8.png)

## 实践场景

- **字段名被改**：前端说参数传对了，后端却报错，抓包一看，原来字段名被改成了下划线。
- **加载慢的真相**：用户说图片加载慢，抓包对比时间线，发现大部分时间花在等 DNS 解析上。
- **学协议**：学习协议的时候，你甚至能直接看到 TCP 三次握手、四次挥手是怎么走的。

![三格分镜：字段名变下划线、时间多花在 DNS 解析、看到 TCP 三次握手与四次挥手](/blog/什么是抓包-从数据包-混杂模式到-https-明文的完整解析/scene-9-9.png)

## 看包时最值得盯的三个信息

- **时间戳**：告诉你每次交互花了多久。
- **IP 和端口**：告诉你是谁在跟谁说话。
- **状态码和响应体**：告诉你对方是答应了还是拒绝了。

把这三样串起来，一次故障的来龙去脉基本就清楚了。

![三张卡片：时间戳=交互耗时，IP+端口=谁跟谁，状态码+响应体=答应或拒绝](/blog/什么是抓包-从数据包-混杂模式到-https-明文的完整解析/scene-10-10.png)

## 限制：HTTPS 抓不到明文

今天大部分流量都是 HTTPS，直接抓下来的内容是加密的，只能看到密文。

想看到明文，常用的办法是中间人代理：让工具生成一张自己的证书，装到电脑或手机上，设备信任它之后，流量先经过工具解密，再重新加密发出去。

这也是为什么抓 HTTPS 几乎都要先装证书。

![HTTPS 抓明文流程：密文 → 生成证书 → 装入设备 → 信任 → 解密 → 重新加密发出](/blog/什么是抓包-从数据包-混杂模式到-https-明文的完整解析/scene-11-11.png)

## 具体操作可以按四步走

1. **明确目标**：是查某个接口还是分析整体流量，先想清楚要回答什么问题。
2. **选工具并配置**：选好工具，并配置好代理和证书。
3. **用过滤条件筛请求**：比如只看某个域名或某个 IP，不然几万个包会看晕。
4. **回到时间线对比**：对比请求和响应，定位异常。

![四步流程：明确目标 → 选工具并配置代理证书 → 过滤条件 → 回时间线对比定位](/blog/什么是抓包-从数据包-混杂模式到-https-明文的完整解析/scene-12-12.png)

## 常见误区与合规边界

抓包会碰到别人的数据，存在隐私和合规风险。

你只能抓自己有权限分析的流量，比如自己的设备、自己负责的测试环境。在公共网络上随意截取他人数据，在很多地方是违法的。

![合规边界对比：可以抓自己的设备与测试环境，不能抓公共网络上他人的数据](/blog/什么是抓包-从数据包-混杂模式到-https-明文的完整解析/scene-13-13.png)

## 常见问题

**抓包是不是黑客专属技能？** 不是。它是排查网络问题、理解协议、验证接口最常用的手段，开发、测试、运维都会用到。

**为什么抓 HTTPS 看不到内容？** 因为这部分流量是加密的，直接抓下来只能看到密文；想看到明文，通常要用中间人代理并让设备信任工具生成的证书。

**抓包会不会有合规风险？** 会。你只能抓自己有权限分析的流量，在公共网络上随意截取他人数据在很多地方是违法的。

## 总结

抓包的本质，是把网络通信变成一份可以逐条翻看的对话记录。

它的核心能力就两个：过滤和对比，先缩小范围，再找出哪一次交互和预期不一样。

学会这一点，你排查网络问题的方式，就会从反复试错变成有依据地定位。
