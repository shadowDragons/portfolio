## 什么是域名？

域名（Domain Name）是互联网命名空间中的人类可读名称。它用 `example.com` 这类容易记忆和输入的文字，代替用户直接记忆 IP 地址，并通过 DNS 找到对应的网络服务。

![域名的定义、分层结构、后缀和解析方式概览](/blog/what-is-domain-name/scene-1.png)

简单说，**域名是便于人使用的名字，IP 地址是网络通信使用的地址，DNS 负责在两者之间查询映射。**

域名不必只代表“一台服务器”或“一个网站”。同一个域名可以返回多个 IP 地址，也可以用于邮件、接口、文件服务和域名验证；多个域名也可以指向同一个 IP 地址。因此，更准确的说法是：域名为网络资源提供稳定、可读的名称。

## 域名和 IP 地址是什么关系？

域名和 IP 地址分别解决“方便人记忆”和“方便网络寻址”两个问题。用户输入域名，DNS 查询得到当前可用的 IP 地址，浏览器再用这个地址建立网络连接。

![IP 地址是机器使用的数字地址，域名是便于人类记忆的名称，DNS 负责转换](/blog/what-is-domain-name/scene-2.png)

可以把两者理解为门牌名与坐标：

| 概念 | 主要使用者 | 作用 | 示例 |
| --- | --- | --- | --- |
| 域名 | 人、应用程序 | 提供稳定、可读的名称 | `www.example.com` |
| IPv4 地址 | 网络设备、操作系统 | 标识 IPv4 网络中的通信目标 | `203.0.113.25` |
| IPv6 地址 | 网络设备、操作系统 | 标识 IPv6 网络中的通信目标 | `2001:db8::25` |
| DNS | 客户端与 DNS 服务器 | 查询域名对应的 IP 或其他记录 | A、AAAA、MX、TXT 等 |

域名和 IP 并不是严格的一对一关系：

- 一个域名可以对应多个 IP，用于负载分配、容灾或就近访问。
- 多个域名可以共享一个 IP，由 Web 服务器根据域名返回不同网站。
- 域名可以先通过 CNAME 指向另一个名称，再解析到 IP。
- 服务器更换机房或 IP 后，网站可以只更新 DNS 记录，继续使用原域名。

图中的具体 IP 用于解释概念，不代表该域名在任何时间和地区都固定返回这个地址。**域名提供相对稳定的入口，IP 则可以随部署变化。**

## 域名由哪些层级组成？

域名采用树状分层结构，并且从右向左逐级变得具体。完整域名 `www.example.com.` 可拆成根域、顶级域、二级域和子域四部分。

![完整域名从右向左由根域、顶级域、二级域和子域组成](/blog/what-is-domain-name/scene-3.png)

```text
www.example.com.
│   │       │  └── 根域（root），通常省略
│   │       └───── 顶级域（TLD）：com
│   └───────────── com 之下注册的名称：example
└───────────────── 子域或主机名：www
```

各层之间用点号分隔：

1. **根域 `.`**：DNS 命名空间的最高层。浏览器输入时通常省略末尾的点。
2. **顶级域 `.com`**：也叫 TLD，由相应注册局管理。
3. **注册域名 `example.com`**：通常是个人或组织通过注册商取得使用权的主体名称。
4. **子域 `www.example.com`**：由 `example.com` 的管理者自行创建，可用于网站、API 或其他服务。

“二级域名”在中文语境中容易产生歧义。按 DNS 层级，`example` 是根域下的第二级标签；但一些人也会把 `www.example.com` 口语化地称为“二级域名”。讨论配置时，使用“注册域名”和“子域名”通常更清楚。

此外，可注册边界不一定永远是“最后两个标签”。例如 `example.co.uk` 常是注册域名，而 `.co.uk` 是公共后缀。程序若要判断可注册域名，应使用 [Public Suffix List](https://publicsuffix.org/)，不能只按点号数量截取。

## 域名和网址有什么区别？

域名只是网址中的主机标识部分；网址的正式名称是 URL（Uniform Resource Locator，统一资源定位符），它还可以包含协议、端口、路径、查询参数和片段。

![域名只标识访问的主机，完整 URL 还包含协议、路径和查询参数](/blog/what-is-domain-name/scene-4.png)

以这个 URL 为例：

```text
https://www.example.com:443/article?id=1#intro
└─┬─┘   └──────┬──────┘ └┬┘└──┬───┘└─┬─┘└─┬─┘
 协议          主机名      端口  路径    查询  片段
```

| URL 部分 | 示例 | 作用 |
| --- | --- | --- |
| 协议 | `https` | 规定如何通信 |
| 主机名 | `www.example.com` | 标明要连接的网络服务 |
| 端口 | `443` | 标明主机上的服务入口；HTTPS 默认端口通常可省略 |
| 路径 | `/article` | 指向服务中的具体资源 |
| 查询参数 | `id=1` | 向服务传递查询条件 |
| 片段 | `intro` | 指向资源内部位置，通常不会随 HTTP 请求发给服务器 |

所以，`example.com` 是域名，`https://example.com/article?id=1` 才是完整网址。URL 的主机部分也可以直接写 IP 地址，此时网址中甚至不包含域名。

## DNS 如何让域名真正发挥作用？

DNS（Domain Name System，域名系统）是分布式命名系统。它根据域名查询 A、AAAA、MX、TXT 等资源记录，其中 A 和 AAAA 记录分别用于获得 IPv4 和 IPv6 地址。

![DNS 系统在易记的域名与机器可识别的 IP 地址之间建立映射](/blog/what-is-domain-name/scene-5.png)

DNS 经常被比作“互联网电话簿”，但它不是一台保存所有域名的中央服务器。真实的 DNS 由递归解析器、根服务器、顶级域服务器和权威 DNS 服务器共同组成，并通过分层委派完成查询。

DNS 负责回答“这个名称有哪些记录”，不负责下载网页。浏览器拿到 IP 后，通常还要完成 TCP 或 QUIC 连接、TLS 握手和 HTTP 请求，才能获得页面内容。

## 输入域名后，DNS 解析经过哪些步骤？

一次没有命中缓存的典型查询，会从本地缓存开始，再由递归解析器沿“根服务器 → 顶级域服务器 → 权威 DNS 服务器”的委派链取得结果。

![从浏览器缓存、递归解析器到根服务器、顶级域服务器和权威 DNS 的解析流程](/blog/what-is-domain-name/scene-6.png)

以查询 `www.example.com` 的地址为例：

1. **检查本地信息**：浏览器和操作系统先检查可用缓存与本地名称配置。
2. **请求递归解析器**：本地没有答案时，把查询交给运营商、企业网络或公共 DNS 提供的解析器。
3. **询问根服务器**：递归解析器未命中缓存时，获取 `.com` 顶级域服务器的地址。
4. **询问顶级域服务器**：解析器获得 `example.com` 权威 DNS 服务器的委派信息。
5. **询问权威服务器**：权威服务器返回 `www.example.com` 的 A、AAAA、CNAME 或其他正式结果。
6. **缓存并返回**：解析器按 TTL 缓存结果，再返回给客户端。
7. **建立连接**：浏览器选择可用 IP，继续建立连接并发送 HTTP 请求。

这个流程是便于理解的完整路径。现实中大多数查询会利用某一层缓存，不一定每次都访问根服务器；CNAME、DNSSEC 验证、重试和不同浏览器的加密 DNS 设置也可能增加步骤。因此，解析时间没有固定值，不能笼统保证“都在几百毫秒内完成”。

## 域名如何注册，又由谁管理？

注册域名获得的是在约定期限内使用该名称的权利，而不是把域名永久买断。注册人通过注册商提交申请，注册商再与对应顶级域的注册局交互，把注册信息和 DNS 委派写入注册系统。

![域名从可用性查询、注册商购买、注册局记录到续费的完整流程](/blog/what-is-domain-name/scene-7.png)

域名体系中的角色可以这样区分：

| 角色 | 主要职责 | 常见例子 |
| --- | --- | --- |
| ICANN | 协调全球 DNS 根区、通用顶级域政策与注册体系 | 制定 gTLD 基本规则、认可注册商 |
| 注册局（Registry） | 运营某个顶级域的注册数据库 | 管理 `.com` 或某个国家代码顶级域的机构 |
| 注册商（Registrar） | 面向用户提供查询、注册、续费与管理服务 | 用户实际购买域名的平台 |
| 注册人（Registrant） | 在注册期内持有并管理域名使用权 | 个人、公司或其他组织 |
| DNS 托管商 | 托管权威 DNS 记录 | 可与注册商相同，也可以独立选择 |

常见注册流程是：查询是否可用、选择注册期限、填写联系信息、付款、设置权威 DNS，然后按时续费。域名过期后的宽限期、赎回期和删除时间由后缀、注册局与注册商政策共同决定，并非所有域名都遵循完全相同的周期。

注册后应启用多因素认证、注册锁和到期提醒。对业务域名来说，账号被盗或忘记续费都可能同时影响网站、邮件和 API。

## 为什么短域名通常更有价值？

短、易拼写且与品牌相关的域名，可以降低输入、记忆和口头传播成本。它的价值主要来自稀缺性、品牌匹配度和使用便利性，而不是域名越短就必然带来更高搜索排名。

![京东从 360buy.com 切换到 jd.com 展示短域名在记忆和品牌传播上的价值](/blog/what-is-domain-name/scene-8.png)

京东曾使用 `360buy.com`，后来启用 `jd.com`。两个字母与“京东”的品牌缩写对应，拼写更短，也更适合口头传播和移动端输入。类似的优质短域名数量有限，因此可能在二级市场产生较高交易价格。

选择域名时可以检查四点：

- **容易听懂**：口头说出后，对方不必反复确认拼写。
- **容易输入**：避免不必要的连字符、数字和易混淆字符。
- **接近品牌**：名称能与产品、公司或个人身份建立联系。
- **降低风险**：注册前检查商标、历史用途和相似域名，避免侵权或混淆。

短只是一个因素。一个略长但含义明确、没有商标风险的域名，往往比难以理解的短字符串更实用。

## 域名后缀有哪些类型？

域名后缀通常指顶级域。常见类型包括通用顶级域（gTLD）、国家或地区代码顶级域（ccTLD），以及后来开放的大量新通用顶级域。

![域名后缀分为通用顶级域、国家或地区代码顶级域和新通用顶级域](/blog/what-is-domain-name/scene-9.png)

| 类型 | 示例 | 原始或常见含义 | 选择时关注什么 |
| --- | --- | --- | --- |
| 通用顶级域 | `.com`、`.net`、`.org` | 商业、网络、组织；目前部分后缀已广泛通用 | 用户熟悉度、名称是否可注册 |
| 国家或地区代码顶级域 | `.cn`、`.jp`、`.uk` | 对应国家或地区的两字母代码 | 本地规则、资质、备案或争议政策 |
| 新通用顶级域 | `.app`、`.tech`、`.shop` | 行业、用途或品牌语义 | 续费价格、注册限制和用户认知 |
| 被跨场景使用的 ccTLD | `.io`、`.ai` | 分别是英属印度洋领地和安圭拉的国家或地区代码 | 注册局政策、地缘与长期运营风险 |

`.io` 和 `.ai` 经常被科技公司使用，但从 DNS 分类看，它们仍是 ccTLD，并不是“新通用顶级域”。后缀的营销用法不会改变其注册局和政策归属。

选择后缀时，至少比较首年价格、续费价格、转入转出规则、注册资格、目标用户熟悉度和当地法律要求。后缀能传递定位信号，但不能单独证明网站可信。

## `.edu` 和 `.gov` 为什么不能随便注册？

部分顶级域或二级域设有资格限制。以美国的 `.edu` 和 `.gov` 为例，它们分别服务于符合条件的教育机构和政府组织，普通个人或一般企业不能像注册 `.com` 一样直接取得。

![受限域名后缀只允许符合资格的教育或政府机构申请](/blog/what-is-domain-name/scene-10.png)

这里需要注意范围：

- `.edu` 的现行资格规则主要面向符合要求的美国高等教育机构，历史注册者可能适用不同安排。
- `.gov` 面向经过验证的美国政府组织，申请需要身份与授权审核。
- 其他国家可能在自己的 ccTLD 下设置 `.edu.cn`、`.gov.uk` 等层级，规则由各自管理机构制定。
- 有限制不代表绝对安全。用户仍应检查完整域名、HTTPS 证书和页面内容，防范相似拼写、子域误导与账号入侵。

因此，能否注册某个后缀必须查询对应注册局的最新规则，不能只根据后缀字面含义判断。

## 域名有哪些常见误区和限制？

理解域名时，最常见的问题是把名称、地址、网站和所有权混为一谈：

1. **域名不等于网址**：域名是名称，URL 是包含协议、主机、路径等信息的完整地址。
2. **域名不等于网站**：域名可以用于网站，也可以用于邮件、API 和验证；注册域名不会自动生成网页。
3. **域名不一定对应一个 IP**：一对多、多对一和间接别名都很常见。
4. **DNS 不负责传输网页**：它提供名称查询，网页内容由后续的 HTTP 等协议传输。
5. **域名不是永久买断**：需要续费并遵守注册局与注册商规则。
6. **修改 DNS 不会瞬间全球生效**：旧结果可能在 TTL 到期前继续被缓存。
7. **后缀不等于可信保证**：多数开放后缀任何人都可注册，受限后缀也仍可能发生账号或内容安全问题。

## 常见问题

### 域名、网址和网站是一回事吗？

不是。域名是 `example.com` 这样的名称；网址是 `https://example.com/docs` 这样的完整资源地址；网站则是服务器通过一个或多个网址提供的页面和功能集合。

### 有了域名，为什么还需要 DNS？

因为网络连接最终需要可用的 IP 地址或其他服务信息。DNS 保存并查询域名对应的资源记录，让客户端能够从名称找到当前服务入口。

### 一个域名可以对应多个 IP 地址吗？

可以。同一个域名可以返回多个 IPv4 或 IPv6 地址，用于负载分配、容灾和就近访问。客户端最终选择哪个地址，还会受 DNS 响应、网络状况和连接策略影响。

### 域名和主机名有什么区别？

域名是 DNS 命名空间中的名称；主机名通常指 URL 或网络配置中标识主机的名称。`www.example.com` 既是一个域名，也可以作为 URL 的主机名。严格语境下，两者关注点不同，不能在所有协议中完全互换。

### 域名到期后会立即被别人注册吗？

不一定。许多后缀会经历续费宽限期、赎回期和待删除阶段，但具体时长与规则取决于注册局和注册商。重要域名应开启自动续费和多渠道到期提醒，不要依赖过期后的补救窗口。

### `.com`、`.cn`、`.ai` 应该怎么选？

面向广泛用户且希望降低认知成本时，`.com` 通常更熟悉；业务主要面向中国市场时，可以结合品牌保护和合规需求考虑 `.cn`；AI 产品使用 `.ai` 能表达行业语义，但应同时评估价格、规则和长期风险。最终选择应以目标用户、品牌、可用性和运营成本为准。

## 总结：域名在互联网中起什么作用？

域名的核心作用，是在机器使用的网络地址和人类使用的文字名称之间建立可管理的映射。服务器迁移或 IP 改变时，运营者可以更新 DNS 记录，而用户继续通过同一个名称访问服务。

![域名通过稳定映射连接可变化的 IP 地址与人类易记的网站身份](/blog/what-is-domain-name/scene-11.png)

把本文压缩成四句话：

- **域名**是人类可读的网络名称。
- **IP 地址**是网络通信使用的地址。
- **DNS**负责查询域名对应的 IP 和其他资源记录。
- **URL**是在域名或 IP 之外，还包含协议、路径、参数等信息的完整资源地址。

域名不是网址里的普通文字片段。它是互联网分层命名体系中的关键入口，让网络服务拥有可记忆、可迁移、可持续管理的身份。
