# 什么是 Markdown

Markdown 是一套用普通字符来标记文档结构的写法。你在纯文本里敲几个符号，就能让一段文字变成标题、列表、链接或者代码块。

![手绘 Markdown 徽章向外辐射到标题、列表、链接、代码块四个小卡](/blog/什么是-markdown-用普通字符标记文档结构的一套写法/scene-1-1.png)

## 核心机制：格式写在文字本身里

平时写文档，要给一个词加粗，得先选中它，再去点工具栏上的按钮。Markdown 换了个思路：直接在文字两边敲两个星号，这个词就加粗了。

所有格式都写在文字本身里，不需要隐藏的样式表，也不需要复杂的操作界面。

![左侧选中文字再点工具栏按钮，右侧在文字两边敲两个星号即加粗](/blog/什么是-markdown-用普通字符标记文档结构的一套写法/scene-2-2.png)

## 为什么要换一条路

当时有两个现成的选择，都不太舒服。

用 Word 写东西，排版信息藏在一个你看不见的结构里，换台电脑、换个软件，格式就可能跑掉；用 HTML 写网页，一个标题要写成一对尖括号标签，读起来全是噪音。

Markdown 想做的则是中间那条路：写的时候像写纯文本一样轻松，读的时候又能看出结构。

![Word 格式易跑掉与 HTML 尖括号噪音两个问题框，经中间的桥通向轻松写、结构清楚](/blog/什么是-markdown-用普通字符标记文档结构的一套写法/scene-3-3.png)

## 常用语法只有五类

具体到语法，其实少得可怜，常用的就五类：标题、列表、强调、链接、代码。

- 标题：用井号，一个井号是一级标题，三个井号就是三级标题，层级一眼可见。
- 列表：用减号或者数字加点，换行就自动续上。
- 强调：用星号，一个星号是斜体，两个是加粗。

![三张语法卡：标题用井号体现层级、列表用减号或数字加点、强调用星号](/blog/什么是-markdown-用普通字符标记文档结构的一套写法/scene-4-4.png)

- 链接：写成方括号加圆括号，方括号里是显示的文字，圆括号里是网址。
- 代码：用反引号包起来，行内用一层，整段用三层。

记住这一整套符号，你已经能写出九成日常文档了。

![拆解链接与代码两组符号：方括号放显示文字、圆括号放网址，一层反引号行内、三层反引号整段](/blog/什么是-markdown-用普通字符标记文档结构的一套写法/scene-5-5.png)

## 真正干活的是解析器

Markdown 文件本身只是纯文本，后缀一般是 `.md`。它不会自己变成漂亮的页面。

真正干活的是解析器，也就是把 Markdown 读进去、按规则转成网页 HTML 的程序。

![三步线性推进：纯文本 .md 文件经解析器转成 HTML 网页](/blog/什么是-markdown-用普通字符标记文档结构的一套写法/scene-6-6.png)

## 一份源文件，出现在很多地方

同一份源文件可以出现在很多地方：在代码托管平台上它会自动渲染成项目说明页，这就是常见的 README；在笔记软件里可以变成带大纲的文档；在博客系统里可以直接发布成文章。

格式没有绑定在任何一家公司的软件上，十年后你打开它，还是那堆字符。

![一个源文件节点分叉到代码托管平台 README、笔记软件大纲文档、博客文章三个使用场景](/blog/什么是-markdown-用普通字符标记文档结构的一套写法/scene-7-7.png)

## 和 Word、HTML 比，它换来了什么

Word 的优势是所见即所得，适合排版要求高的正式文件，但它的文件结构复杂，用别的工具很难精确读取。

HTML 表达力最强，可控到每一个像素，可代价是写起来啰嗦。

Markdown 牺牲了精细排版，换来的是可读、可改、可版本管理。

![Word、HTML、Markdown 三列对比优势与代价的矩阵表](/blog/什么是-markdown-用普通字符标记文档结构的一套写法/scene-8-8.png)

## 两个被低估的好处

在代码托管平台上，你对 `.md` 文件的每一次修改都会被记录成一行行差异，谁改了什么一眼就能看出来。

纯文本还有一个被低估的好处，是搜索和批量处理。

你的笔记和文档全都是一堆字符，用命令行就能一次搜完所有文件，用脚本就能批量生成目录、做统计。换成二进制文档，这些事就得靠专门的软件一件件来。

![两个好处卡片：修改被记录成一行行差异；纯文本可用命令行搜索、脚本批量处理](/blog/什么是-markdown-用普通字符标记文档结构的一套写法/scene-9-9.png)

## 上手路径：从四样语法开始

最省事的路径是这样的：先装一个支持 Markdown 的编辑器，左边写，右边实时预览，格式对不对当场就能看到。

写的时候不用记全语法，先掌握标题、列表、加粗、链接这四样，就够写出一份结构清楚的笔记了。

等习惯了这个节奏，再去用表格、引用、任务清单这些扩展语法，全程不需要配置任何东西。

![弯曲路径上的三个里程碑：装编辑器左右实时预览、先掌握四样语法、再用扩展语法，终点标注无需配置](/blog/什么是-markdown-用普通字符标记文档结构的一套写法/scene-10-10.png)

## 限制与常见误区

它的边界也很明确：Markdown 没有原生的表格合并单元格，没有精确的字号和行距控制，复杂的图文混排基本做不了。

所以它适合写结构清晰、以文字为主的内容，不适合做海报、合同、精装手册。

![左侧列出三项做不了的能力限制，右侧区分适合与不适合的内容类型](/blog/什么是-markdown-用普通字符标记文档结构的一套写法/scene-11-11.png)

还有一个容易被忽略的点，是它的方言问题。最早的 Markdown 语法描述得比较宽松，不同的解析器在表格、脚注、换行这些地方各有一套做法。

后来出现了一份更严格的规范，叫 CommonMark，把模糊的地方定下来，很多工具都向它靠拢。

所以你在不同平台写 Markdown，大部分语法一致，个别扩展语法可能会有差异。

![宽松语法导致各解析器做法不一，经 CommonMark 规范桥面通向基本统一](/blog/什么是-markdown-用普通字符标记文档结构的一套写法/scene-12-12.png)

## 一个新变化：先接触 Markdown，再接触文档

现在很多人第一次接触 Markdown，不是在写文档，而是在跟 AI 对话。

用标题分层、用列表拆步骤、用代码块贴代码，输出更整齐，复制出来也更好整理。

这说明它的价值不在于好看，而在于用极低的成本把想法分出层次。

![中心是 AI 对话卡片，向外辐射标题分层、列表拆步骤、代码块贴代码三个用法](/blog/什么是-markdown-用普通字符标记文档结构的一套写法/scene-13-13.png)

## 常见问题

**用 Markdown 需要记住全部语法吗？**

不需要。先掌握标题、列表、加粗、链接这四样，就够写出一份结构清楚的笔记了。

**同一份 Markdown 在不同平台显示会完全一样吗？**

大部分语法一致，个别扩展语法可能会有差异，因为早期语法描述比较宽松，不同解析器在表格、脚注、换行上各有一套做法。

**Markdown 文件会自己变成漂亮的页面吗？**

不会。它本身只是纯文本，真正干活的是解析器，把 Markdown 按规则转成网页 HTML。

**Markdown 适合做海报或合同吗？**

不适合。它没有精确的字号和行距控制，也没有原生表格合并单元格，复杂的图文混排基本做不了。

## 总结

Markdown 用井号、减号、星号、方括号和反引号这几样普通字符标记文档结构：写的时候像写纯文本一样轻松，读的时候又能看出结构。

它牺牲了精细排版，换来的是可读、可改、可版本管理，适合结构清晰、以文字为主的内容；不适合做海报、合同和精装手册。
