## 什么是 C 与 C++：先理清血缘关系

![手绘封面：C 与 C++ 两枚只差两个加号的标签，下方三块卡片标注血缘关系、关键差异、适用场景与初学选择](/blog/c-和-c-有什么区别-从血缘关系到六大差异-适用场景与学习路径/scene-1-1.png)

C 和 C++ 这两个名字只差两个加号，实际却是两门设计目标不同的语言。C++ 最早叫“带类的 C”，是在 C 的基础上加上了类机制。

因此 C++ 保留了 C 的语法骨架：指针、数组、结构体、预处理、编译链接流程几乎一样。

但 C++ 并不是 C 的严格超集。有些合法的 C 代码放进 C++ 编译器就编不过，比如某些隐式类型转换会被直接拒绝。

![从左到右的演化路径：C 加上类机制成为“带类的 C”，下方标注保留的指针、数组、结构体、预处理、编译链接流程，末端警示“不是严格超集”](/blog/c-和-c-有什么区别-从血缘关系到六大差异-适用场景与学习路径/scene-2-2.png)

## 核心差异一：编程范式

C 是面向过程的语言，程序就是一批函数加一批数据结构，你写的是操作数据的步骤。

C++ 是多范式语言，既能面向过程，也能面向对象，还能写泛型。你可以在 C++ 里定义类、把数据和操作封装在一起、用继承和多态做扩展。

这个能力改变的是代码怎么组织，不只是语法好不好看。

![左右分栏对比：左侧函数模块串起数据块表示面向过程，右侧并列面向过程、面向对象、泛型三种能力与数据操作封装的小盒子](/blog/c-和-c-有什么区别-从血缘关系到六大差异-适用场景与学习路径/scene-3-3.png)

## 核心差异二：内存管理

C 只有 malloc 和 free，申请和释放完全靠人记得配对：忘了就泄漏，重复释放就崩溃。

C++ 有 new 和 delete，并且提供了一整套叫 RAII 的机制，也就是把资源绑定到对象的生命周期上，对象析构时自动释放。再配合智能指针，绝大多数场景下你不需要手写 delete。

![左侧 malloc 与 free 需人工配对及泄漏、重复释放崩溃的警示，中间木板桥标注 RAII 资源绑定对象生命周期，右侧对象析构自动释放与智能指针图标](/blog/c-和-c-有什么区别-从血缘关系到六大差异-适用场景与学习路径/scene-4-4.png)

## 核心差异三：抽象能力

C 的结构体只能装数据，想给数据配行为，只能写一批以指针为参数的函数。

C++ 的类可以把数据和操作放在一起，还能用模板写出与具体类型无关的代码。标准库里的容器、算法、迭代器，就是靠类加模板搭起来的。

![自下而上三层递进：底层结构体只装数据配指针参数函数，中层类与模板，顶层标准库容器、算法、迭代器](/blog/c-和-c-有什么区别-从血缘关系到六大差异-适用场景与学习路径/scene-5-5.png)

## 核心差异四：类型检查

C 没有函数重载，同名函数只能有一个，参数对不对要靠调用方自觉。

C++ 支持函数重载、引用、const 常量性，类型检查也更严格，编译器能提前拦住不少错误。代价是报错信息可能很长，模板报错尤其难读。

![C 与 C++ 两列表格，逐行对照函数重载、引用、const 常量性、类型检查强度与报错信息长度](/blog/c-和-c-有什么区别-从血缘关系到六大差异-适用场景与学习路径/scene-6-6.png)

## 核心差异五：性能代价

C++ 有一条设计原则叫零开销抽象：你不用就不付代价，用了也不比手写更慢。所以类和模板本身几乎不产生运行开销。

这条原则并不意味着所有特性都免费。虚函数要走一次间接调用，异常处理这些特性有额外成本。

C 的代价模型更简单，你能直接把代码对上汇编。

![中心写零开销抽象，四周辐射不用就不付代价、用了不比手写更慢、类与模板几乎无开销、虚函数一次间接调用、异常处理有额外成本，边缘标注 C 的代价模型更简单](/blog/c-和-c-有什么区别-从血缘关系到六大差异-适用场景与学习路径/scene-7-7.png)

## 核心差异六：编译与工程

C 编译快、依赖少，一个源文件对应一个目标文件，结构非常直接。

C++ 的模板在编译期展开，头文件层层嵌套，大型项目编译时间能到几十分钟，工程管理也更复杂。

![左右对比：左侧一个源文件对应一个目标文件、依赖少编译快，右侧模板编译期展开、头文件层层嵌套并标注几十分钟与工程管理更复杂](/blog/c-和-c-有什么区别-从血缘关系到六大差异-适用场景与学习路径/scene-8-8.png)

## 实践场景：各自适合什么

写操作系统内核、驱动程序、单片机固件、通信协议栈，用 C。这些场景要求可控的内存布局、稳定的二进制接口、极小的运行时，C 更合适，而且生态积累了几十年。

写游戏引擎、桌面应用、浏览器、数据库、高频交易系统，用 C++，因为它们既需要复杂的数据结构和抽象，又不能牺牲性能。

![顶部“怎么选”分出两支：左支用 C 挂操作系统内核、驱动程序、单片机固件、通信协议栈，右支用 C++ 挂游戏引擎、桌面应用、浏览器、数据库、高频交易系统](/blog/c-和-c-有什么区别-从血缘关系到六大差异-适用场景与学习路径/scene-10-9.png)

两者还能混合编译：C++ 用 extern "C" 这个声明关掉名字修饰，就能直接调用 C 的库。这也是为什么大量底层库用 C 写、上层用 C++ 调。

![右侧 C++ 上层代码经标有 extern "C" 的桥梁连接左侧 C 底层库，下方警示带写很多 C++ 项目里满是 C 风格代码、指针到处传](/blog/c-和-c-有什么区别-从血缘关系到六大差异-适用场景与学习路径/scene-9-10.png)

## 学习路径：先学 C 为什么划算

学习路径上，先学 C 是划算的。你会真正理解指针、内存布局、栈和堆、编译链接这些底层概念。

这些知识在 C++ 里不会消失，只会被封装起来。跳过 C 直接学 C++，往往在遇到段错误和内存泄漏时无从下手。

## 限制与常见误区

- 误区一：把 C++ 当成 C 的超集。有些合法的 C 代码在 C++ 里编不过，迁移时不能默认兼容。
- 误区二：以为用了 C++ 就自动拥有抽象。很多 C++ 项目里仍然满是 C 风格代码，指针到处传，等于用 C++ 的复杂度写 C 的代码，反而更容易出错。
- 限制一：C++ 的编译与工程成本更高。模板在编译期展开、头文件层层嵌套，大型项目编译时间能到几十分钟，工程管理也更复杂。
- 限制二：抽象不是零成本。零开销抽象说的是“不用就不付代价”，而虚函数要走一次间接调用、异常处理有额外成本。
- 限制三：C++ 的类型检查更严格，换来的是可能很长的报错信息，模板报错尤其难读。

## 常见问题

**C++ 是 C 的超集吗？**

不是严格超集。C++ 从“带类的 C”演化而来，保留了 C 的语法骨架，但有些合法的 C 代码放进 C++ 编译器就编不过，比如某些隐式类型转换会被直接拒绝。

**C 和 C++ 的内存管理差在哪？**

C 只有 malloc 和 free，申请与释放完全靠人记得配对，忘了就泄漏，重复释放就崩溃。C++ 有 new 和 delete，并用 RAII 把资源绑定到对象的生命周期上，对象析构时自动释放，再配合智能指针，绝大多数场景下不需要手写 delete。

**C++ 一定比 C 慢吗？**

不一定。类和模板本身几乎不产生运行开销，零开销抽象的意思是不用就不付代价、用了也不比手写更慢。但虚函数要走一次间接调用，异常处理有额外成本。C 的代价模型更简单，你能直接把代码对上汇编。

先学 C 是划算的。你会真正理解指针、内存布局、栈和堆、编译链接这些底层概念，这些知识在 C++ 里不会消失，只会被封装起来。跳过 C 直接学 C++，往往在遇到段错误和内存泄漏时无从下手。

## 总结

C 是一把锋利的刀，简单、直接、可控；C++ 是一整套工具箱，在保留底层控制力的同时，给你组织大型程序的手段。

两者的差异不在于语法难易，而在于你愿不愿意为抽象付出工程复杂度。理解这一点，选语言就不再是纠结，而是根据场景做判断。
